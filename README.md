# 架阁 · rust-llm

> **上下文不重算。**

企业级 AI 办公工作台的**上下文 / 注意力引擎服务**。

| 层 | 名字 | 用在哪 |
|---|---|---|
| 产品 | **架阁**（jià gé） | 登录页、顶栏、销售与文档（面向客户） |
| 引擎 | `rust-llm` | 组件名、仓库名、服务端文档（不对外当品牌） |
| 代码 | `web` / `workbench` / `admin` | 目录、路由、包名（中性技术名） |

"架阁"取自宋代的**架阁库**——存放档案文书的官署。名字即业务：收拢上下文、按序归档、需要时取用、每次都记账。
slogan「上下文不重算」是承诺：同一份前缀，付过一次就不再付第二次。

> 定名前必须做商标检索（第 9 类软件 / 第 42 类 SaaS）。公开网络里 `文枢`、`青简` 已被办公 AI 产品占用，`架阁` 在软件领域未见占用。

纯服务后端 + 纯客户端。系统的全部价值是"把不变的内容按最低单价反复使用"：管上下文、管预算、管命中；不管 Agent、不管工具、不管内容判定。

## 架构

```
        ┌───────────── web（浏览器，React）─────────────┐
        │      chat 面              admin 面            │
        └────────────────┬─────────────────────────────┘
          控制帧 JSON    │    数据帧 原始字节
                         ▼
┌──────────────── engine_server_core ──────────────────┐
│   接入 → 身份 → 隔离 → 上下文 → 分发 → 计量 → 通知     │
│   ┌────────┐      ┌──────────┐      ┌──────────┐      │
│   │  wire  │◀─────│  server  │─────▶│  engine  │      │
│   └────────┘      └────┬─────┘      └──────────┘      │
└────────────────────────┼─────────────────────────────┘
                 config/ │ data/          └──▶ 上游 LLM
```

服务端有两条腿：对内向浏览器开门（axum），对外主动发起模型请求（HTTP client）。**流的源头是我们那条出网请求，所以我们拥有它，也能掐断它。**

## 目录

```
engine_server_core/
├─ core/        地基：ID / 错误映射 / 五个 trait / 配置 / 遥测
├─ db/          存储实现（SQLite）：schema / pool / migrate / users / msgs / ledger
├─ engine/
│   ├─ user/    用户管理：模型 / 引导管理员 / 管理用例 / 门禁 / 登录态
│   ├─ server/  服务器管理：HTTP 路由 / WS 升级 / 连接 / 健康 / 优雅停机
│   └─ meter/   计量：用量 / 命中 / 聚合 / 导出
├─ route/       LLM API 管理：端点 / 路由表 / 选端点 / 冷却反馈
├─ context/     上下文：模型 / 追加 / 组装 / 预算 / 恢复 / 状态机
├─ stream/      流：身份 / 出网 / 直通 / 便签 / 取消
├─ wire/        对外形状：控制帧 / 错误码
├─ config/      routes.json
├─ data/        运行时产物（不入库）
└─ tests/       e2e

web/
├─ src/pages/{login,workbench,admin}
├─ src/lib/{rpc,stream}
└─ src/theme/
```

**划分规则**：域 = 回答一类业务问题；域内一个文件 = 一个用例（动词命名）；数据结构放该域的 `model.rs`。

**两条隔离规矩**：
1. 业务域只认 `core/traits.rs`，**不许 `use db`** —— 这是以后能换 PG 的唯一保证。
2. `engine` 各域不许碰网络与硬盘，只做判断；碰 IO 的只有 `db/`、`engine/server/`、`stream/`。

## 六条不变量

| # | 不变量 | 违反的后果 |
|---|---|---|
| I1 | 前缀只有一个生成者（服务端） | 多端拼前缀 ⇒ 命中率随机崩且不可复现 |
| I2 | 同一会话单写者、顺序追加 | 前缀顺序打乱 ⇒ 从改动点起全部 miss |
| I3 | 响应侧不回写（只去壳 + 旁路读） | provider 字段变更传导给我们，且引入解析崩溃点 |
| I4 | 一切状态按用户分区 | 跨用户串流 = 事故 |
| I5 | 控制面与数据面分离 | 加管理功能会污染热路径 |
| I6 | 服务端不做任何内容判定 | 一旦开例，规则引擎会长成巨兽 |

辅助约束：**工具结果永远进尾部增量区，不进前缀。**

服务端对内容只有四个动词：**存档 / 拼装 / 转发 / 计量**，四个都不判定。

## 一条流的一生（只有 5 个瞬间）

| 瞬间 | 谁触发 | 做什么 | 归谁管 |
|---|---|---|---|
| 1 发起 | 前端用户 | **只在这里验用户**（是不是我们的、还能不能用） | 用户管理 |
| 2 在走 | 上游 | 什么都不做，原字节递过去 | — |
| 3 中断 | 用户点停止 / 掉线 / 配额到顶 | 掐断上游那条请求 | 用户管理 + 流 |
| 4 异常 | 上游（429 / 5xx / 卡住 / 吐一半断） | 给前端明确失败便签，记一笔 | 流 |
| 5 结束 | 上游吐完 | 记用量、落档 | 上下文 + 计量 |

鉴权只发生在第 1 瞬间，对前端用户做一次；上游不认识我们的用户，只认我们带的 key。

## 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 存储 | **SQLite 单机**（WAL + 单写线程） | 事务、崩溃可恢复、单文件备份；负载形状天然匹配 |
| 可迁移 | 业务只认 trait / SQL 只用可移植子集 / ID 自己生成 / 存档可导出 | 换 PG = 写一个新实现 + 搬一次数据 |
| 控制帧 | WS Text + JSON | 前端是 TS，JSON 原生；控制帧每请求仅 2~3 条 |
| 数据帧 | WS Binary + 上游原始字节 | 0 改写；靠 WS 帧类型天然分流 |
| 编码 | 不引 postcard | JS 侧要自写解码器，省下的只有 100 字节 |
| 预算 | 默认 9K 软顶，超了丢尾部 | 不摘要；输出最贵（12 vs 命中 0.5） |
| 前端 | React 19 + TS + Tailwind 4 + shadcn | 主题参照成熟后台的观感，代码自研 |

## 直通（数据面）

一次转发 = 读一块 + 打 1 字节标签 + 写一块，**20~100 µs**；上游出字间隔是 20~80 ms，首字要 300 ms~2 s。**快三个数量级——慢的永远是上游，不是我们。**

五个必须做对的开关：

| # | 开关 | 不做会怎样 |
|---|---|---|
| 1 | `TCP_NODELAY`（WS 两端） | Nagle + delayed ACK 插入 40 ms 级尖刺 |
| 2 | 反向代理关缓冲（nginx `proxy_buffering off`） | 代理攒满才吐，延迟爆炸 |
| 3 | 不开 `permessage-deflate` | 小帧压缩多花 CPU、多一次 flush |
| 4 | 一帧一块，不攒不切 | 攒大块 = 人为加延迟；切太碎 = 白多几倍 syscall |
| 5 | 前端按 `requestAnimationFrame` 合并渲染 | 服务端再快也会被 DOM 重排拖成幻灯片 |

**背压**：单连接待发上限 **1 MB**，超限即断开，前端带 `seq` 重连续传。

- 绝不丢中间块——文本流丢字就是错内容。
- 1 MB ≈ 上千块 ≈ 数十秒积压；正常会话到不了这个量，所以这条上限只会在病态情况下触发。
- 25 万次写/秒（5k 并发 × 50 块/秒）在现代 Linux 上是常规量，不为此做合并。

## 不做（不再讨论）

| 不做 | 为什么 |
|---|---|
| Agent 运行时 / 工具执行 / 审批 | 工具属客户端，服务端零知识 |
| 内容判定（拦截 / 脱敏 / 敏感检测 / 审计留证） | 拦截必须与执行能力同侧；审计留证在客户端或外部 SIEM |
| 摘要压缩 | 丢尾部更便宜且不引入幻觉 |
| 协议翻译（OpenAI ↔ Anthropic ↔ Gemini） | 我们是透明管道，不是翻译网关 |
| 路由 / 渠道管理 UI | 路由靠 `config/routes.json` + 管理 API |
| 敏感信息提醒（密码检测） | 拦不住刻意的，救不了粗心的 |
| 复用 new-api 前端代码 | AGPLv3 网络条款 ⇒ 我们整站须开源；只炒观感 |
