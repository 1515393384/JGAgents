## 1. 定位与非目标

**定位（一句）**：企业级 AI 办公工作台的**上下文/注意力引擎服务**——纯服务后端 + 纯客户端。

**非目标（`[否]`，不再回炉）**

| 不做的 | 为什么 |
|---|---|
| Agent 运行时（plan/todo/工具执行/审批） | 工具与循环属客户端，服务端零知识 |
| 内容判定（拦截/脱敏/敏感检测/审计留证） | I6；拦截必须与执行能力同侧 |
| 摘要压缩 | 超预算直接丢尾部；查询能力另做 |
| 协议翻译（OpenAI↔Anthropic↔Gemini 互转） | I3；我们是透明管道，不是翻译网关 |
| 路由/渠道管理 UI | 路由靠 `config/routes.json` + 管理 API，不做界面 |
| 桌面壳 / Tauri / Leptos 前端 | 客户端统一 Web（React 19 + TS） |
| 计费套餐、模型广场、插件市场 | 网关的领域，不是引擎的领域 |

## 2. 部署形态 `[定]`

```
客户端（Web：React 19 + TS，chat 面 + admin 面）
    │  控制帧 = WS Text(JSON)   /   数据帧 = WS Binary(上游原始字节)
    ▼
服务端（单个 Rust 二进制：axum + tokio）
    接入 → 身份 → 隔离 → 上下文 → 分发 → 计量 → 通知 → 生命周期
    │                                        │
    │ 读写 dev──data/（conv JSONL、账本）      └──▶ 上游 LLM（OpenAI 兼容，去壳直通）
    ▼
config/routes.json（记录 API：endpoint 清单 + 权重 + key_env）
```

**控制帧用 Text(JSON)、数据帧用 Binary(原始字节)**——
利用 WS 自带的帧类型做零成本分流，服务端不需要读 payload 就知道该转发还是该解析。

## 4. 依赖方向 `[定]`

```
      web（TS）──只看 wire 的 JSON 形状（docs/wire.md）
              │
           service（bin）──────────────▶ 上游 LLM
           │        │
           │        └──▶ engine（纯逻辑，被调用）
           └──▶ wire（帧类型）
```

| 目录 | 必须 | 禁止 |
|---|---|---|
| `engine` | 纯函数、可穷举单测 | IO、tokio、axum、`std::time::now`、随机数（一律注入）、`spawn` |
| `wire` | 只有数据结构与编解码 | IO、业务判断、依赖 engine |
| `service` | 接入/身份/隔离/分发/计量/通知/生命周期 | 改写响应 payload（只许去壳）、持有内容级策略 |
| `web` | 渲染与输入 | 持有 key、直连上游、参与拼装前缀 |

依赖只能单向：`service → {engine, wire}`，`wire ⇸ engine`，`engine ⇸ wire`。

## 5. 六条不变量 `[定]`

| # | 不变量 | 违反的后果 | 怎么被守住 |
|---|---|---|---|
| **I1** | 前缀只有一个生成者（服务端） | 多端拼前缀 ⇒ 命中率随机崩且不可复现 | 客户端请求只含 `user/conv/seq/msg` |
| **I2** | 同一 conv 单写者、顺序追加 | 前缀顺序打乱 ⇒ 从改动点起全部 miss | 每 conv 一条串行队列 |
| **I3** | 响应侧不回写（只去壳 + 旁路读） | provider 字段变更传导给我们，且引入解析崩溃点 | 数据帧 Binary 原样转发 |
| **I4** | 一切状态按 `user` 分区 | 跨用户串流＝事故 | 每个 conv 请求先过 user 分区检查 |
| **I5** | 控制面与数据面分离 | 加管理功能会污染热路径 | 控制帧 JSON / 数据帧 opaque，物理分流 |
| **I6** | 服务端不做任何内容判定 | 一旦开例，规则引擎会长成巨兽 | 四个动词白名单：存档/拼装/转发/计量 |

**辅助约束**：工具结果**永远进尾部增量区，不进前缀**（否则"工具自由"会把命中率杀掉）。

## 6. 服务端七个职责 `[定]`

| # | 职责 | 一句话 | 不做 |
|---|---|---|---|
| **A** 接入 | 收连接、验版本、设上限 | 首帧必须 `Hello`；版本不符如实回我方版本再关；帧大小/连接数/空闲超时有硬上限 | 不留半开连接、不做协议转换 |
| **B** 身份 | token → user | 连接建立时验一次，之后调用都带 user 上下文 | 不引 JWT/OIDC（day-1 不透明 token 查表） |
| **C** 隔离 | 一切状态按 user 分区 | 跨 user 的 conv 一律 `NotFound`（不泄露存在性） | 不做共享会话 |
| **D** 上下文 | 存档、拼装、裁剪、锚点 | append-only JSONL；9K 预算裁尾部；前缀字节恒定；重启可恢复 | 不摘要、不检索编排 |
| **E** 分发 | 选上游、发请求、原字节回送 | 粘性 + 权重 + 冷却；旁路计量；支持取消 | 不改写响应、不做多模型编排 |
| **F** 通知 | 只在状态变化时说话 | 流 `Begin/End/Error`；上下文变更；预算回执；`since_seq` 续传 | 不逐 token 包装 |
| **G** 生命周期 | 起、停、重载、恢复 | 优雅 drain；配置热更新失败保留旧表；崩溃后 replay | 不做集群编排 |

## 7. 四个动词 `[定]`

服务端对"内容"只有四个动作：**存档 / 拼装 / 转发 / 计量**。四个都不判定。

| 动作 | 位置 | 是否判定 | 是否阻断 |
|---|---|---|---|
| 存档 | 会话侧（JSONL） | 否 | 否 |
| 拼装 | 请求侧（assemble + 预算） | 否（只按预算排序/裁剪） | 否 |
| 转发 | 响应侧（去壳 + 原字节） | 否 | 否 |
| 计量 | 响应侧旁路（usage/字节/耗时/transitions） | 否 | 否 |

预算回执（超 9K、尾部将被裁）属**资源事实**，不属内容判定，允许通报。

## 9. 线格式 `[待]`

| 项 | 建议 | 理由 |
|---|---|---|
| 控制帧 | **WS Text + JSON** | 前端是 TS，JSON 原生；控制帧每请求 2~3 条，体积可忽略 |
| 数据帧 | **WS Binary + 上游原始字节** | 0 改写；WS 帧类型即可分流 |
| 编码 | **不引 postcard** | JS 侧需自写解码器；省 40% 只省 100 字节，不划算 |
| 首帧 | `Hello{ver, caps, token}` → `Welcome{ver, caps}` | 版本不符如实回我方版本再关 |
| 请求 | `ChatSend{user, conv, seq, msg}` | `conv` 定位上下文、`seq` 幂等 |
| 续传 | `since_seq` | 客户端无状态，断线必须能接回 |
| 错误码 | `BadFrame / UnsupportedVersion / Unauthorized / NotFound / StaleGeneration / Budget / Canceled / Internal` | 数值稳定，前端可无条件分支 |

> 注：旧计划写"文本帧一律拒绝"，本文改为"Text=控制帧、Binary=数据帧"——这是**有意的改变**，理由见上表。

## 12. 隐私与加密（`[定]` 分层，机制延后实现）

**一句原则**：加密只承诺能做到的事，不玩话术。

| 层 | 做法 | 管理员能否看到 | 状态 |
|---|---|---|---|
| 密码 | Argon2id（每用户随机 salt + 服务端 pepper，pepper 在 KMS 不在库）；登录态随机令牌，库里只存令牌哈希；密码最少 12 位，弱口令拦下，登录限速 | 不能反推 | `[待]` 随 server core 一起落 |
| 日志 | **正文永不落日志/错误栈/panic**，只记 conv_id、token 数、耗时、命中率 | 看不到 | `[待]` |
| 存储 | 客户端加密后上传，服务端只存密文；DB 与备份同密钥静态加密 | 只能看到密文 | `[待]` |
| 密钥 | 空间 KEY 由客户端随机生成，**服务端不持有、不转存**，库里只放 `sha256(KEY)` 校验指纹 | **不能** | `[待]` |

**内容可见性 = 不看 + 两种保证方式（`[定]`）**
- 任何档位：**不看内容、不用于训练、日志不落正文**（政策 + 最小权限 + 双人审批 + 审计）。
- **免费版**：KEY 由我方托管（免输 KEY），所以是**政策约束**——我们能做到但不去读。
- **付费档（VIP / SVIP / Office Agent / 企业）**：KEY 归用户，服务端不持密钥、不持明文，是**密码学保证**——不是"不去读"，是"读不了"。

| 环节 | 做法 |
|---|---|
| 存储 | 客户端加密后上传，服务端只存密文 |
| 上下文复用 | 前缀在客户端组装；服务端只见"前缀指纹 + token 计数"，用于计费与命中率 |
| 模型调用 | 客户端解密后组请求 → ① 隧道中转（我们只转字节，TLS 在客户端与厂商之间端到端结束）② 直连（不经我们） |
| 审计 | 只记访问元数据：谁、何时、哪个空间/文件；**没有"解密动作"可记，因为解不开** |

**被直接否掉的形态**

| 形态 | 为什么否 |
|---|---|
| 服务端可解密 + 解密留审计 | 任何"能解"都等于后门，用户明确要求不留口（`[否]`） |
| 本地模型 / 离线版 | 跑在用户机器上，快慢与显存不是我们的承诺，已下线（`[否]`） |
| 服务端明文零接触 + 服务端优化 + 更省钱 | 三者不可能同时成立（`[否]`） |

**档位只差三件事（`[定]`）**：办公能力（改写深度 / 提醒 / 模板 / 协作席位）、可用模型范围、空间与席位数。**与内容可见性无关**——安全底线四档一致，不当卖点。

**加解密不计费**（`[定]`）：加密、解密、密文复用都含在档位里，四档一致，不单独收费。

**Web 端诚实边界（`[定]`）**：网页由服务端分发，前端理论上可被替换，所以浏览器里的 E2EE 是**承诺不是数学证明**；可验证 E2EE 只承诺给桌面客户端（签名 + 可复现构建）。

### 12.1 安全声明口径（`[定]`）

**原则**：承诺动作与通告义务，不承诺"绝对安全"；也不写"概不负责"。

| 段 | 写什么 |
|---|---|
| 能承诺（可审计） | TLS 1.3、AES-256 静态加密、Argon2id + pepper、最小权限、正文不落日志、不用于训练 |
| 不能承诺（结果） | 任何系统都无法保证绝对不被攻破；不写"绝对安全" |
| 通告义务 | 确认泄露后 72 小时内告知受影响范围、处置进展与责任划分 |
| 用户责任 | 密码保管、不在公共设备登录、私密空间密钥丢失即数据不可恢复 |

落点：注册页一行小字（当前已实现）+ 服务条款正本（`[待]` 商务侧起草）。

### 12.2 SVIP「云空间加密版」：KEY 与命名（`[定]`）

**命名铁律**：KEY 只指空间加密钥匙，模型不许叫 Key。

| 概念 | 统一叫法 | 内部名 | 说明 |
|---|---|---|---|
| 账号登录口令 | 登录密码 | `password` | 只存 Argon2id 哈希，不进加密链 |
| 空间加密钥匙 | **KEY** | `space_key` | **创建时随机生成，仅首次展示，我方不存** |
| 用什么模型 | 架阁提供的模型 / 自备模型 | `model_source` | 自备模型只需填厂商凭据，与空间解密无关 |

**KEY 的存法（`[定]`）**

| 存法 | 我们掌握 | 结论 |
|---|---|---|
| **只存在用户手上，服务端不存** | 只存一把校验指纹 `sha256(KEY)`，用来判断"你输的 KEY 对不对" | `[定]` |
| 服务端加密托管 | 能解 | `[否]` 等于自建后门，直接否掉 |

- **KEY 随机生成**（客户端 CSPRNG，≥128 bit，展示为分组字符串），创建完成后只显示一次，允许用户抄走/下载；关掉就不再出现。
- 丢失后果：**该空间所有内容永久解不开，包括我们**（没有第 2 份）。校验指纹只能判真假，无法反推 KEY。
- 加密链：内容在客户端用 KEY 派生的数据密钥 AES-256-GCM 加密 → 上传密文 → 服务端只做字节中转与存储，不参与解密。
- **模型这一侧**（`[定]`）：SVIP 给"更多模型"或允许自备；自备只绑一把厂商凭据，不做多渠道/余额/限速/切换——那是网关的事。
- **中转 ≠ 看得懂**（`[定]`）：默认走服务端字节中转（连接稳、多端接续、断线续传，流原样转回），服务端不见明文；也可切直连。
- **技术支持边界**（`[定]`，大白话，不甩锅）：能帮账号、空间、计费、连接/中转/续传/多端不同步，以及自备模型的连通性排查；帮不了 KEY 本身——KEY 不在我们手上，丢了两边都无解，这是加密的代价。
- 换设备：登录 + 输入 KEY 即可继续用，不需要重新生成。

### 12.3 定价口径（`[定]`）

**四档，一档比一档多"能改到什么程度"，不是按 token 卖；安全底线四档一致。**

| 档 | 价（示意） | 一句话 | 文档改写 | 协作编辑 | 模型 |
|---|---|---|---|---|---|
| 档位 | 价 | 一句话 | 文档改写 | 空间数 | 席位数 | 存储 | 可用模型 |
|---|---|---|---|---|---|---|---|
| 免费版 | ¥0 / 永久 | 2 席以内小团队 | 只读预览 | 1 | 2 | 2 GB | 架阁基础集 |
| VIP 服务端处理 | ¥49 / 席 / 月 | 全量模型，按席起步 | 单段改写 | 3 | 10 | 50 GB | 架阁全量 |
| SVIP 云空间加密版 | ¥99 / 席 / 月 | KEY 只在你手上 | 单段改写 | 10 | 25 | 200 GB | 全量 + 可自备 |
| Office Agent 计划 | ¥199 / 席 / 月起 | 阁吏直接改 Word / Excel / 标书 | 整篇 · 批量 · 逐段接受 | 不限 | 不限 | 1 TB | 全量 + 可自备 |
| 企业 | 另议 | SSO、审计导出、自带 KMS、私有部署 | 整篇 · 批量 | 不限 | 不限 | 按需 | 全量 + 可自备 |

- **有成本的资源一律体现层级**：空间数、席位数、存储、网盘挂载（— / 1 个 / 3 个 / 不限）四档逐级递增，不许出现三列同值的"不限空间 · 按席"式写法——同值行等于没写。

- **全部档位共同承诺（横条，不占表格行）**：① 不读取内容、不用于训练、日志不记正文；② 付费档密钥用户保管、服务端不存也无法解密；③ 审计仅记访问元数据（操作人、时间、文件标识）；④ 相同开头只计一次、加解密不计费、多端续看与续传可用；⑤ 模型用量按采购成本价直出、0 加价、账单按 token 明细可核；⑥ 不承诺固定折扣，上游调价同步调整，大额走预付额度包。
- 已下线 **离线版（本地模型）**：跑在用户机器上，快慢与显存不是我们的承诺。
- **阶梯口径**：涨价只买"办公能力 / 模型范围 / 席位"，绝不买"安全性"。早前把端到端加密单独做成中间一档是反的（越贵越安全这条线会断），现行做法是安全全档同底。
- 铁律 4 条：① 按席位月付，不按 token 抽成；② 相同开头只计一次；③ 加解密不计费；④ 模型用量按成本价直出。
- **开票与免责口径**（弹窗脚注，一字不改）：按席位月付，不按 token 抽成；模型用量按成本价直出；**可按订单开具发票**。以上为示意价，最终以合同与账单为准；企业私有部署另议。
- **模型计费口径**：四档一律采购成本价直出、0 加价，账单按 token 明细可核。**不把"原厂 / 8 折 / 6 折 / 3.5 折"写进档位**——那等于以用量作赌注，席位费扛不住用量波动；真折扣只做**预付额度包**（买量一次谈定，用不完不退不转），风险留在用户侧。省钱叙事走上下文复用，不走折扣。
- 展示：登录页一条价格带（只报数）+ 右上角「定价」胶囊，细则走**弹窗**，不跳页、不新开路由。表按大厂写法：表头 = 方案 + 价 + 一句话，行名用名词短语，分 **办公能力 / 模型与上下文 / 空间与容量 / 安全与计费** 四组 + 一条承诺横条 + 脚注；SVIP 打「推荐」；宽屏走表，窄屏按档纵向列。
- **注册页不选档**：注册只收用户名 + 密码，档位在定价弹窗 / 空间设置里选。

- **提醒与模板不锁档**（`[定]`）：付费各档一律给，不拿它当升级钩子；差异只在**通知渠道**——站内 / 邮件 / 短信（短信按条计费，含资费与模板报备成本）。
- **APP 端不单独做档位**（`[定]`）：端不收费，多端续看与断点续传本就是卖点。

价格只写在 `web/src/lib/route-copy.ts` 的 `planPrice`（价）、`planGroups`（对照行）与 `planIncluded`（全档一致条）三处，定价弹窗与登录页价格带共读，不许页面里硬编码。
