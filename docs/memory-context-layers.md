# 记忆与上下文分层 [定]

本文件记录一件事：上下文如何被驱动、新知识放哪、用户偏好放哪。
证据来源：OpenBitFun `crates/assembly/core/src/agentic/memories/*`、`session/compression/compressor.rs`。

## 1. 一句话

上下文不是"存历史"，是**按可变性分层**：不可变段尽量长、可追加段尽量短、可外置段不进上下文。

| 层 | 内容 | 变化频率 | 落点 |
|---|---|---|---|
| 不变段 | 系统规矩 + 工具声明 + 已固化偏好 | 会话级 | 内存快照，按 `prefix_id` 缓存字节 |
| 追加段 | 本轮用户消息、工具往返、记忆写入 | 每轮 | 只允许尾部追加 |
| 外置段 | 被裁掉的旧轮次、长文档 | 不占 token | 文件 + 行号指针 |

驱动上下文的只有三件事：用户消息、工具结果、记忆写入。三者一律进追加段；**禁止插入中段**，否则前缀作废、缓存全失。

## 2. 知识放哪（四处，别混）

1. **工作记忆**：本轮任务状态，内存态，会话结束即弃。
2. **长期记忆**：`mem` 表，条目 + BM25 两跳召回，模型主动调 `recall` 才进上下文。
3. **产物**：文件/文档，只挂句柄或大纲，内容不进上下文。
4. **偏好**：用户设置，固化进不变段（会改变前缀，改一次即重建缓存）。

## 3. 借用 OpenBitFun 的两条 [定]

- **原子切点**：裁窗口/压缩时不得拆开 `assistant.tool_calls` 与其 `tool` 结果（`compressor.rs::atomic_message_units`）。当前 `ctx::fit()` 只按 token 裁，会裁出无父 tool 消息 → 400。必修。
- **历史外置 + 行号指针**（`append_transcript_reference`）：被裁轮次落文件，上下文只留「完整历史在 `<uri>`，索引在 a-b 行，先读索引再 Grep」。补上裁窗口后信息全丢的洞，且不需要模型生成摘要。

## 4. 不借用 [定]

- 文件 + 模型自己 Grep 检索记忆：本地 BM25 是 O(1)，它要多轮工具调用，既慢又破坏前缀。
- Phase1/Phase2 后台 job 表 + watermark + 整合 agent：单机、10K 预算下成本远大于收益。
- 模型生成压缩摘要走常规路径：多一次调用、多一次付费，摘要文本变化还会让前缀失效。

## 5. 未决 [待定]

1. 外置段文件放哪、什么时候清理（会话关闭 / LRU）。
2. `recall` 命中条目是"模型主动调"还是"命中即注入末尾"——注入会改追加段，需先测命中率变化。
3. 偏好条目改动如何触发缓存重建（改一条 = 前缀全重算，是否需要分级：会话级偏好 vs 账号级偏好）。
