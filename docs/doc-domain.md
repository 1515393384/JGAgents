# 文档域定稿（标书场景）

> 状态：`[定]` = 已确认；`[草案]` = 待你过目；`[待定]` = 未决。
> 原则：文档版 git —— 一个数据模型、一种 patch、一条写回路径。

## 1. 文档角色 `[定]`

一套标书里三种文档，权限不同，必须在模型里写死：

| role | 来源 | 权限 |
|---|---|---|
| `tender` | 甲方招标文件（买/下载） | 只读；约束与评分基准；**AI 永不改写** |
| `bid` | 我方投标文件（骨架派生 + 填写） | 唯一可写；patch 只对它生效 |
| `asset` | 素材（证照、业绩、历史段落） | 只读；按需检索插入 |

## 2. 入口 `[定]`

1. 导入 `tender` → 抽章节骨架 + ★/▲ 废标条款 + 评分点 → 派生 `bid` 骨架
2. 复用历史标书/素材 → 以 hunk 插入目标章节
3. 从零新建（少数，纯技术方案正文）→ 同一通道

"派生骨架"不是自由创作：拷原包 → 留格式章节标题与表格 → 清空待填内容 → 产出 `bid v1`，复用同一 patch 通道删块。

## 3. 寻址 `[定]`

只有一个直源：行号 + 上下文。**不存在第二套 ID。**

```
doc(rev) → blocks(story, idx, kind, level, heading_path, text, hash, tokens)
```

- `idx` 即行号；`story` 区分 body / headerFooter / 表格单元格 / textbox，防止 ID 撞车
- 大纲 = `level ≤ 3` 查询，AI 拿目录 + 行号区间 + 字数
- 不做 `anchor_id` 表、不做四级锚点、不做模糊匹配

## 4. patch 协议 `[定]`

变更一律 unified hunk（同 git），段落级：

```
@@ story=body -1024,6 +1024,6 @@
 上下文段（3 行）
-旧段落文本
+新段落文本
 上下文段
```

应用：`patch = { base_rev, hunks[] }`

- 上下文 3 行做**唯一匹配**，0 fuzz；0 处或多处命中 → 整条拒绝
- 通过后段落级替换：新文本继承原 `pPr` + 首 run 的 `rPr`
- receipt：改前 hash、改后 hash、变更行数、耗时
- `base_rev` 非当前版本 → `STALE`，前端重拉，不做静默合并

**字符级 diff 只用于展示，永不回写。** 导出内部一律净稿；红线 `w:ins/w:del` 由 hunk 在导出时反推生成，是独立函数，不是第二编辑通道。

## 5. 错误码 `[定]`

`STALE`（版本过期）、`NO_MATCH`（上下文 0 命中）、`AMBIGUOUS`（上下文多处命中）、`LOCKED`（条款锁定）、`UNSUPPORTED`（story 或结构不支持）。

## 6. 明确删除（避免重复实现）`[定]`

- `anchor_id` / 节点 ID 表 → 行号 + 上下文
- 四级锚点（paraId / 指纹 / 模糊 / LCS）
- 字符级 patch 应用
- track changes 编辑通道 + 净稿通道两套
- `doc_refs` 交叉引用（一期）
- 前端富文本编辑

## 7. 已知代价 `[定]`

段落级替换 + 继承首 run 格式 ⇒ 段内混排（半句加粗、段中上标）改写后统一为首 run 格式。要保段内混排需升级字符级 patch，二期再碰。

## 8. `.doc` → `.docx` 转换风险（标书场景）

只转一次：入站转 docx，出站给 docx + PDF，不回 `.doc`。原件永久只读留档。

| 级别 | 风险 | 后果 | 检查手段 |
|---|---|---|---|
| 高 | 招标文件规定"必须按原格式编制、不得改动格式" | 转换导致版式变化 → 投标文件可能被判无效 | 转换前标记"格式严格"项目，走只读建议模式，不改文件 |
| 高 | 域代码失效（TOC、PAGEREF、SEQ 表号如"表2-3"） | 目录/交叉引用断，页码错 | 转换前后统计域数量，导出时提示更新域 |
| 高 | 页码/总页数（"共X页 第X页"）随字体与行距变化 | 页码不连续 → 常见废标点 | 转换后标记页数变化，要求人工确认 |
| 中 | 多级自动编号错乱或变硬文本 | 后续插入段落编号连带错 | 检查 `numbering.xml` 与 `numPr` 保留情况 |
| 中 | 样式名本地化（"标题 1" vs "Heading 1"） | 章节树识别失败、误判结构 | 按 `outlineLvl` + 正则兜底，不只认样式名 |
| 中 | EMF/WMF 矢量图被栅格化 | 盖章件/图纸打印失真 | 统计图片数与格式，逐条比对 |
| 中 | 分节、首页不同、单双面、页眉页脚差异 | 版式偏移、红头错位 | 比对分节数与页眉引用 |
| 低 | 文本框/艺术字（封面）位置漂移 | 封面字错位 | 覆盖率检查 |
| 低 | 字体缺失（宋体/仿宋_GB2312） | 换行重排、页数变化 | 记录字体清单，缺失即告警 |

缓解措施 `[定]`：
1. 原件只读留档，转换只产出工作副本
2. 转换前后跑"保真体检"（域数、图片数、样式数、分节数、页数五项差异清单），交用户确认
3. 转换器优先级：Word COM（Windows，保真最高）→ LibreOffice headless；WPS CLI 作兜底（能力未核）
4. 交付优先 `.docx` + `.pdf`；甲方硬性要 `.doc` 时由用户用 WPS/Word 另存，不由我们二次转换
5. 格式严格项目提供"只读建议模式"：不生成新文件，只出改动清单
